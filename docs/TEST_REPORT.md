### 其他驗證

- **金額守恆**：單元測試以 3000 步隨機操作（投幣、押注、開始、結算、猜大小、轉分、退幣），每一步檢查「口袋 + 機台 + 押注 + 得分 + 機台收入 − 累計派彩 = 100」。
- **賠率**：`exactRtp()` 精確列舉，八門皆 89.95%–90.02%；整個引擎模擬 60 萬局，實測值在理論值 ±1.5% 內；各燈位停燈頻率在設定值 ±0.4% 內。
- **贈燈**：2 萬次抽樣，贈燈只出現在「再一次」、數量 1–3、不重複。
- **版面**：機台完整落在視窗內、保持 600:1180 比例、無捲軸；觸控目標最小 50×53 CSS px（押注鍵）；viewport 禁止縮放並支援 `viewport-fit=cover` 與安全區。
- **無障礙**：14 個實體按鍵都有 `role` 與 `aria-label`（押注鍵含賠率與目前押分）；狀態文字同步到 `aria-live` 區域；Space/Enter 可操作聚焦中的按鍵。
- **無 emoji**：測試掃描 DOM 沒有 emoji 字元，全部圖案為程式繪製的 SVG。

### 第 14 項：音效

- 自動化：以 `OfflineAudioContext` 離線渲染 12 種音效，每一種都有聲音且峰值 0.13–0.58（< 0.98）；同時疊加所有音效的最壞情況峰值 0.58（限幅器有效）；靜音時峰值 < 1e-8。
- 真實點擊：在瀏覽器窗格以真實滑鼠點擊投幣孔後，`AudioContext.state` 為 `running`。
- 修正過的問題：曾發現短促機械聲（押注、滴答）比硬幣聲小 5–10 倍，已按事件調整音量平衡；嗡鳴降低到不蓋過滴答聲。

## 測試中發現並修正的問題

1. **跑燈計時器在瀏覽器中拋出 `Illegal invocation`**（預設計時器以物件方法呼叫 `setTimeout`）。Node 測試不會發現，是實際點 START 才暴露。已修正，並加上動畫失敗時直接結算的保護，機台不會卡死。
2. SVG 刮痕路徑多了一個 `M`，造成主控台錯誤。已修正。
3. 硬幣動畫依賴 `requestAnimationFrame`，背景分頁暫停時投幣後顯示器不更新。已加保底計時器。
4. 音效相對音量不平衡（見上）。
5. 單元測試的金額守恆斷言一開始漏算「機台收走的押注」，是測試寫錯，不是遊戲錯誤；已修正並保留。

## 限制（誠實說明）

- **沒有在真實 iPhone / 真實 Safari 上測過。** 版面與互動是在內建瀏覽器窗格（Chromium 系）用 375×667、390×844、430×932、320×568 的視窗模擬驗證。iOS 特有的行為（音訊解鎖時機、`touchend`、橡皮筋捲動、安全區實際數值）只依規格與慣例處理，未實機確認。
- 沒有人耳實聽音效；只驗證了有聲、不爆音、相對音量與靜音。音效「像不像」是主觀的，且為程式合成，不是實機錄音。
- E2E 用合成 `PointerEvent`（沒有「使用者啟動」），所以自動化裡的 `AudioContext` 狀態不能代表手勢解鎖；該項靠另外的真實點擊驗證。
- 跑燈中途分頁被切到背景時，瀏覽器會降低計時器頻率；回到前景會直接跳到終點並結算（已實作，但未做自動化測試）。
- 一次只測了一個瀏覽器引擎。
