# 規則、賠率模型與回收率（RTP）

所有判定都在 `js/engine.js`；設定在 `js/config.js`。`tools/solve-weights.mjs` 可重新求解權重。
證據等級請看 `docs/HISTORICAL_NOTES.md`。

## 1. 一局的流程

1. 投幣：口袋 −NT$10，機台分數 +10。
2. 按水果鍵押分（每次 1 分，每門最多 50）。押分當下就從機台分數扣除。
3. 按 START：**引擎先用 `crypto.getRandomValues()` 決定結果**（含贈燈），並把結果存進 localStorage。
4. 動畫只負責把燈走到預定位置；動畫計時不是亂數來源。
5. 動畫結束後 `settle()` 結算（冪等，只會派彩一次）。中獎的得分放在「得分」欄，不會自動併入機台分數。
6. 得分可以：按 START 轉入機台分數；按 WIN→CREDIT／CREDIT→WIN 鍵在得分與投幣分數間轉分（單按 1 分，按住越久越快）；猜大／猜小；或按退幣（連同機台分數一起退出）。
7. 退幣：機台分數 + 未開始的押注 + 得分，全部轉回口袋，並在退幣盤掉出硬幣。

跑燈中途重新整理頁面：下次載入時會補完結算（押注已被收走、得分照發），不會因為離開頁面而取消這一局。

## 3. 再一次

停在再一次時，隨機贈送 1、2 或 3 個燈（各 1/3）。贈燈從 20 個有圖案的燈位依停燈權重抽出，不重複。
每個贈燈各自與押分比對，中獎各自累計（主燈位的再一次本身不派彩）。

## 4. 理論回收率

押任何一門 1 分，期望派彩（含再一次贈燈）為：

| 圖案 | 單押該門的 RTP | 直接停中的機率 |
|---|---|---|
| 蘋果 | 89.99% | 14.82% |
| 橘子 | 89.99% | 14.83% |
| 木瓜 | 89.99% | 12.97% |
| 鈴鐺 | 90.02% | 12.04% |
| 西瓜 | 89.99% | 12.05% |
| 雙星 | 89.99% | 11.11% |
| 雙七 | 90.02% | 10.65% |
| BAR | 90.07% | 2.07% |

八門回收率相同（誤差 < 0.1%），所以押幾門、押多少，期望回收率都約 90%，沒有「最划算」的押法。
這個數字是 `exactRtp()` 對 24 個燈位與贈燈完整列舉算出的精確值，不是抽樣估計。
單元測試另外用整個引擎模擬 60 萬局驗證實測值（±1.5% 內）。

**猜大小**：每次抽 1–13，猜小 1–6、猜大 8–13，猜對 ×2。期望回收為 12/13 ≈ **92.3%**，因此不是公平賭局，猜得越多期望越低。

沒有任何隱藏的額外中獎機率或「補償機制」。要改機率，只需修改 `LAMPS` 的 `weight` 並重跑 `node tools/solve-weights.mjs`。

## 5. 金額與限制

| 項目 | 值 | 來源 |
|---|---|---|
| 初始口袋 | NT$100 | 題目指定 |
| 每枚硬幣 | NT$10 = 10 分 | 文件 + 題目 |
| 每分 | 虛擬 NT$1 | 模擬 |
| 每門押分 | 1–50 | 文件 |
| 機台分數上限 | 99999（顯示器五位數） | 模擬 |

### 每日補發（台灣時間 00:00）

- 以 `Asia/Taipei` 的日期判斷（不受裝置時區影響）。
- 日期改變後第一次載入、或頁面回到前景時，口袋現金若低於 NT$100 就補到 NT$100；已經高於 100 不扣。
- 不累加，機台內的分數不受影響。
- 所有金額都是虛擬的，沒有任何金流或兌換。

## 6. 存檔

`localStorage` 的 `xiaomali.v2`：口袋、機台分數、得分、押注、階段、跑燈中的預定結果、最後燈位、補發日期、音效偏好。
載入時逐欄驗證（型別、範圍、押注上限、預定結果與押注重新計算的派彩是否一致）。
任何一項不符就整份丟棄並還原為初始狀態；`localStorage` 無法使用（例如無痕模式）時仍可遊玩，只是不會保存。
